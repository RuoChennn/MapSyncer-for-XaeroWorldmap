# 源码审查与项目模型（2026-10-19）

本轮从 `004fe27` 的实际源码、构建配置、固定实例 JAR 与本次新增运行日志重新建立认知，未将历史分析和测试报告作为依据。审查分支为 `codex/review-sync-scope-lan-dimensions`。

## 系统如何工作

`libs/core` 负责 MCA/NBT 读取、按地表与洞穴层扫描、方块与生物群系转换、Xaero 二进制输出；它不依赖游戏运行时。`libs/platform-api` 定义配置、网络载荷和平台接口。`libs/common` 组织转换、差量判断、限速发送、客户端写盘与重载；涉及 Minecraft 类型的公共流程通过四个 MC 锚点参与编译。`libs/mc-1.20`、`mc-1.21`、`mc-1.21.11`、`mc-26` 对应四组游戏 API；各 `mc-<精确版本>/<loader>` 提供注册、生命周期与配置适配，共 14 个交付目标。

服务端以实际世界维度注册信息及扫描计划定位 region 文件，转换为独立缓存 ZIP。MCA 时间戳用于判断是否需要重新转换；生成缓存保存 ZIP 的时间与哈希。客户端请求携带已成功同步的元数据，服务端按请求范围与半径筛选，再通过哈希／时间策略发送差异。客户端组装 region 分片、异步写盘，成功后提交时间戳；游戏线程负责 Xaero 内存区域卸载与重载。断点恢复依靠已提交元数据重新比较。

**后续目录策略修正（2026-10-20）**：专用服继续使用独立 `server_map_cache`。内置服直接复用 Xaero 实际 `MapWorld.getMainId()` 与 `MapSaveLoad.getRootFolder()` 对应的目录，不再新增 `saves/<存档>/server_map_cache` 地图副本；生成和同步均使用每个维度当前选中的多世界地图，包括原生转换的 `cm$converted`。客户端主线程发布目录快照，服务端按快照读取；共享地图的同步元数据取实际 ZIP 的哈希和修改时间。`--force` 只清理所选地图中的区域 ZIP，保留配置和其他地图。访客仍使用自己的 Xaero 多人目录。10 月 19 日的旧实测只覆盖下文所述的原有独立缓存方案，不能替代此改动的真机验证。

## 本轮修复的风险

- **请求隔离与资源消耗**：元数据分片原先缺少完整的数量、字段和累计字符上限，旧请求可能与新请求混装。新增请求标识、读入前边界检查、累计预算、空闲超时与总时长限制；终止状态客户端明确释放同步状态。
- **旧任务干扰新同步**：服务端旧 worker 的收尾和客户端旧回调可能清理新会话。服务端按请求版本清理，客户端按 generation 与连接校验，并隔离旧写盘计数。
- **转换失败后不再重试**：MCA 时间戳提前提交会把失败区域当作最新。改为所有计划层成功后才提交读取时刻的源时间，毫秒持久化并兼容旧格式。
- **自定义维度冲突与漏识别**：维度类型不能代表维度实例；丢弃 namespace 会混淆同名维度。改用真实 level key、完整 ID 和递归存储路径，支持 `minecraft:` 自定义维度、嵌套路径及 Xaero 的 `%`／尾点编码。
- **LAN 注册与路径冲突**：客户端注册请求处理器会覆盖同 JVM 内置服的处理器；房主缺少 ServerData、默认无 mw 子目录。已修复注册、真实地图根目录与多世界目录选择；独立缓存方案后续调整为上文的原生目录复用。
- **错误的成功统计与重载**：失败写盘不计成功并保留 partial 恢复；跨维度下载仅重载当前显示维度；排空重载队列后释放状态。
- **自动任务生命周期**：关闭 autosync 同时取消等待执行的进服任务；定时更新支持 23:59、忙时重试，接受生成任务后才记完成日期；切存档重置维度与 MCA 缓存实例。

## 新增半径限制

配置 `syncRadiusRegions=0` 默认关闭。管理员指令：Fabric `/mapsyncerserver radius <X>`，Forge／NeoForge `/mapsyncer radius <X>`；省略 X 查看当前值。非负整数立即保存，对新请求生效。

以请求时玩家所在 region 为中心，使用 region 网格方形范围 `abs(dx) <= X && abs(dz) <= X`。一个 region 为 512×512 方块，坐标使用 floorDiv；例如 X=1 最多允许当前维度 3×3 个 region 位置，地表和洞穴共用边界。开启限制时 `sync all` 也仅发送玩家当前维度；0 恢复跨维度与全范围同步。此设置限制本次下载，不删除客户端已有地图，也不限制服务端生成范围。

## 验证边界

策略、路径、协议拆分、时间戳重试及真实 ZIP 写盘由 `build-target.bat regression` 验证；完整客户端步骤与证据判据见 [客户端回归流程](client-regression-flow.md)。构建与真实运行分别记录，编译成功不能代替功能通过。

后续维护仍需关注 Xaero 反射 API 的版本变化、极大地图目录扫描与元数据预算导致的全量 eligible 重发，以及地图写入期间用户主动切换 Xaero 多世界地图的行为。当前目录在游戏线程收到区域时捕获，异步写盘不再读取可变游戏对象；尚未实际运行的故障／组合会在本轮结果中明确列出。
